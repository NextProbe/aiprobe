# 单价与花费

*[English](pricing.md)*

AIProbe 把 token 数量换算成金额，让发现的问题更容易被推动解决。这份文档说清楚这些数
字从哪来、它们假设了什么，以及怎么换成你实际支付的价格。

一句话版本：token 数量来自你的 provider，单价是工具自带的、对你来说大概略有偏差，而
任何用通用单价算出来的数字都会明确标注。改一个单价只需要填两个数。

## 四种费率，而不是一种

每个模型带四个单价，因为同一次请求，provider 会按四种不同的价格收费：

| 费率 | 覆盖什么 |
| --- | --- |
| 输入（input） | 未走缓存发送的 prompt token，按全价。 |
| 输出（output） | 补全内容，包括 provider 计入输出的推理 token。 |
| 缓存写入（cache write） | 创建一个 prompt 缓存条目。Anthropic 按输入价的 1.25 倍收费。 |
| 缓存读取（cache read） | 缓存命中。Anthropic 按输入价的 0.1 倍收费；OpenAI 同样是 0.1 倍，且不单独为创建条目计费。 |

如果只用一个混合的「每 token 单价」，在本工具最关心的那类会话上会差一个数量级。长时
间运行的 agent 会话绝大部分是缓存读取：一个携带 70 万 token 上下文的 Claude Code 会
话，可能为 46 万次缓存读取付 $0.14、为 22 万缓存写入付 $1.49。把这些压成一个平均单
价，就毁掉了「上下文很大但被缓存了」和「上下文很大而且你在按全价付费」之间的区别——
而这正是一个健康会话和一个坏掉的会话之间的区别。

所以 `aiprobe pricing` 显示四列，花费区块也把账单拆成四行。

## 内置单价从哪来

它们是公开标价，记录于一个固定日期。这个日期会在每一处出现花费的地方一起打印出来，
在 JSON 里是 `list_prices_as_of`。

这张表刻意做得很短。只包含十来个模型：受支持的运行时实际会用到的 Claude 与 GPT 系
列。一张塞满半记半猜数字的长表，比一张短表加一个诚实的「未知」更糟，因为每一条错的
记录都是一个没人会去核对的错误账单数字。

单价是「标价」这件事有两个推论：

- **它们不是你的账单。** 企业协议、承诺消费折扣、Bedrock 与 Vertex 的加价、批量或优
  先级档位，都会改变真实数字。把总额报出去之前，先和真实账单核对。
- **它们会过期。** provider 会定期降价。如果显示的日期相对你记得的最近一次调价已经
  很旧了，就覆盖掉这些费率。

```console
$ aiprobe pricing
 Token prices
 ────────────────────────────────────────────────────────────────────────────
  What token counts get multiplied by. Four rates per model, because
  providers charge four different amounts and a cache read can cost a tenth
  of an input token. Every rate below is what reports actually use, after
  any discount.
  Model                        Input    Output  Cache wr  Cache rd  From
  claude-haiku-4-5           $1.00/M   $5.00/M   $1.25/M  $0.100/M  built-in
  claude-opus-4             $15.00/M  $75.00/M  $18.75/M   $1.50/M  built-in
  claude-opus-5              $5.00/M  $25.00/M   $6.25/M  $0.500/M  built-in
  claude-sonnet-4-5          $3.00/M  $15.00/M   $3.75/M  $0.300/M  built-in
  gpt-5-codex                $1.25/M  $10.00/M         —  $0.125/M  built-in
  ...
  (anything else)            $3.00/M  $15.00/M   $3.75/M  $0.300/M  built-in
```

用 `--lang zh` 可以看中文版本的这张表，网页界面里对应的是**单价**页。

破折号 `—` 表示 provider 没有这一项费率（OpenAI 不为创建缓存条目单独计费），而不是费
率为零。`(anything else)` 是通用兜底单价，不是某个模型。

### 模型名匹配

会话文件里记录的模型名带各种修饰。AIProbe 在查价之前会先做归一化：转小写、去掉厂商
前缀（`anthropic/`、`us.anthropic.`）、去掉 Bedrock 的版本后缀（`:0`、`-v1`）、去掉
末尾的 8 位构建日期，所以 `claude-sonnet-4-5-20250929` 能找到 `claude-sonnet-4-5`。

它还会把一小份白名单里的修饰词解析到基础模型：`-latest`、`-thinking`、`-preview`、
`-beta`。

它**不会**解析一个从没见过的版本号。`claude-opus-4-7` 不会继承 `claude-opus-4` 的价
格，即使前者以后者为前缀——因为它们是价格差很多的不同代际：opus-4 是 $15/M，而 4-5
这一代是 $5/M。接受这种匹配曾让一个真实会话的花费被报成大约三倍，而且没有任何迹象表
明这里做了猜测。

未列出的版本会落到下面的通用单价，并且会被点名。

## 通用单价

没有自己费率的模型，会按一个兜底费率计价，当前是每百万 token $3/$15。
`aiprobe pricing` 里把它显示为 `(anything else)`。

由它算出的每个数字都会被标注、写明是哪个模型、并说明怎么修正：

```
   近似值：claude-opus-4-7 没有单价记录，这里用了通用单价 $3.00/M。执行
   `aiprobe pricing --init` 填上真实单价，这个数字才算准。
```

这是对最初设计的一次改变。最初的做法是把这种模型报为「未知」，理由是「编出来的数字比
没有数字更糟」。这个原则对**没有标注的**数字是对的，但在这里错了：任何使用比内置表更
新的模型的人，会完全看不到花费——这不是更诚实，只是更没用。一个你能看见并能修正的粗略
数字，胜过一个你无从下手的空白。

在价格文件里用 `default` 设置它：

```json
{ "default": { "input": 3, "output": 15 } }
```

填 0 就是关掉它，回到明确的「未知」：

```json
{ "default": { "input": 0, "output": 0 } }
```

注意：这个兜底值绝不会用来充当汇率。按 credit 计费的运行时仍然不会得到凭空换算出的美
元数字——见[什么时候花费是未知的](#什么时候花费是未知的)。

## 用你自己的单价

生效的费率有两个地方能看到：终端里的 `aiprobe pricing`，以及 `aiprobe serve` 里的
**单价**页。两者都会显示每个模型的四种费率、标出每行是内置还是自定义、并写明要编辑哪
个文件。网页是只读的——服务端除了分析历史什么都不写——所以编辑发生在文件里。

```console
$ aiprobe pricing --init
Wrote ~/.aiprobe/pricing.json
Edit the rates to match your invoice. Set "discount" to the fraction off list you
get, so 0.3 means you pay 70%.
```

`--init` 会把整张内置表写出来，所以改一个费率就是改一个数字，不需要知道 schema。它拒
绝覆盖已存在的文件：跑两次不能把你手填的费率冲掉。

```json
{
  "currency": "USD",
  "discount": 0,
  "default": { "input": 3, "output": 15 },
  "models": {
    "claude-sonnet-4-5": { "input": 3, "output": 15 },
    "our-self-hosted-llama": { "input": 0.05, "output": 0.05, "cache_read": 0 }
  },
  "note": "自由文本，工具不读，用来记录这些数字的出处"
}
```

**每个模型只需要两个数。** 费率都是每**一百万** token 的价格，缓存费率在你不另行说明
时由 `input` 推导：

| 字段 | 必填 | 默认值 |
| --- | --- | --- |
| `input` | 是 | — |
| `output` | 是 | — |
| `cache_write` | 否 | `1.25 × input`，这是 Anthropic 的收费方式 |
| `cache_read` | 否 | `0.1 × input`，Anthropic 和 OpenAI 都是这个比例 |

对于不为创建缓存条目计费的 provider，把 `cache_write` 显式写成 `0`——OpenAI 就是这
样，`--init` 正是为此为 GPT 系列写出了那个 0。字段省略就走推导；显式写 `0` 就是零。

`models` 里的任何内容都优先于内置表，内置表从没听说过的模型会直接被加进来。渲染出的
表格会把每行标为「自定义」或「内置」，所以你能看出哪个是哪个。

给每个模型都配齐四种费率是最初的设计，结果是一个没人愿意打开的文件：为了改一个数要填
八个，其中七个还得去查。

解析不了的文件会被报告然后忽略：你会收到一条告警并用上内置单价，而不是一次失败的分
析。为了一个多余的逗号丢掉整份报告，是笔糟糕的交易。

文件以 `0600` 权限写入。它不含密钥，但它是你的配置。

## 折扣

`discount` 是**相对标价打掉的比例**，取值 0 到 1。`0.3` 表示打掉 30%，也就是你付
70%。

这个说法在英文里有歧义，在中文里更糟——中文的「折扣」习惯上指的是乘数而不是减掉的部分
（七折 = 付 70%）。所以每处输出都会把两种表述同时写出来：

```
单价来源：AIProbe 内置，标价日期 2026-09，已打掉 30%（按标价的 0.70 倍付费）。
```

大于等于 1 的值会被拒绝而不是被截断，因为最可能的错误是把 30% 写成 `30`，而把它默默
当作「全部免费」会比报错更糟。

任何分析命令上的 `--discount` 都会为本次运行覆盖文件里的值。由于 `0` 本身是一个有意
义的折扣，这个 flag 的默认值是 `-1`，含义是「没给，用文件里的」。

## 「可省回」值多少钱

可省回这个数字是唯一一处「显而易见的算法」是错的地方，所以值得说清楚。

可省回的 token **不**按未缓存的输入价计价。它们按会话实际支付的每 prompt token 单价
计价：

```
有效输入单价 = (输入$ + 缓存写入$ + 缓存读取$) / prompt token 数 × 100 万
```

原因是大部分可回收的上下文本来就是可缓存的。MCP 工具 schema 处在缓存前缀里；一个被读
了三次的文件，有两次是从缓存里取的。会话为携带它们支付的只是输入价的一小部分。把这些
浪费按完整输入价计价，在内置的 demo 会话上算出了**账单只有 $1.65、却声称能省
$5.95**——这个数字不只是不精确，而是自相矛盾地不可能，也是让读者对报告里其他每个数字
失去信任的最快方式。

用有效单价之后，demo 报告的是花了 $1.65、可省回 $0.95：占金额的 57%，对应 token 的
58%。两者吻合，而这正是之前没通过的那个合理性检查。有一个测试断言：可省回永远不能超
过已经花掉的钱。

值得知道的几个推论：

- 可省回**永远是估算值**，带前导 `~`，即使会话自身的花费是精确的。它背后的浪费数字是
  分析结果，不是计费数据。
- 它在一个意义上是下限，在另一个意义上是上限：各项浪费数字之间可能重叠，所以总量是
  「任何单一修复能拿回多少」的上限；但无法测量的部分被排除在外，所以它在另一个方向上
  又是低估。报告会把两点都写出来。
- 每条发现的花费用的是同一个单价，所以它们加起来不可能超过整个会话的花费。

## 什么时候花费是未知的

当运行时不上报 token 计数器时，没有**实测**的花费，但仍然有一个数字——见
[没有 token 计数器时](#没有-token-计数器时)。只有在完全没有记录模型的情况下，这个区
块才会是空的，因为那时没有任何费率可以套用。

最后这种情况不是假设：**Cursor 不记录是哪个模型回答的**，所以一份 Cursor 报告根本不显示
花费。不是零，也不是猜测——没有费率可以套用，随便挑一个就等于编造答案。Cursor 报告的其他
每个区块仍然有效，因为它们描述的是对话本身，而不是账单。

即使已经给出了推导数字，`unknown_reason` 仍会记录为什么没有实测值：

| 原因 | 含义 | 该怎么做 |
| --- | --- | --- |
| `no_token_counters` | 运行时不上报 token 用量，所以数量和缓存划分都是推导的。 | 读那个推导出的数字，把它当下限。 |
| `billed_in_credits` | 运行时按自己的单位计费，这个单位会被原样上报。 | 同时读 credit 数字和推导出的美元数字。 |
| `no_price_for_model` | 只在你关掉通用单价时出现。模型会被点名。 | 补上它的费率，或者把兜底重新打开。 |

## 没有 token 计数器时

Claude Code 和 Codex CLI 会上报真实的 token 计数器，所以它们的花费是实测的。Kiro、
Kiro CLI 和 Cursor 不上报。对于后面这几个，花费是从转录文件**推导**出来的，而不是直接读
到的：

```
   本次花费                               ~$546.76
   可省回                                  ~$26.12     5%

   缓存写入                  1,737,898      $10.86
   缓存读取              1,071,802,507     $535.90
```

划分来自上下文归因。内容进入 prompt 一次，之后每次请求都会被重新发送，所以「一次性插
入」的总量就是缓存写入那一侧，累计总量剩下的部分就是缓存读取。在一个真实会话上，这个
比例是**99.8% 读取**。

正是这个比例决定了这里要用推导而不是给个界。第一个版本把全部累计上下文按未缓存输入价
计价，结果给出**$5,367，而这个会话推导出来是 $547**——高估了十倍，属于会让读者连报告
其余部分都不再信任的那类数字。未缓存的那个读数仍然会算出来并报告，但作为它本来就该是
的那个上限：

```
   请把它当作下限。缓存条目会过期，会话中间隔太久时，之后的第一次请求会重新
   按全价付费，这一点没有算进来。另一个极端是完全没有缓存，那样要花
   ~$5,367.70。持续使用的会话更接近前面那个较低的数字。
```

所以推导值是地板、上限是天花板，两个都给出，中间的假设被明确写出而不是藏起来。**没
有**被建模的是：

- **缓存过期。** provider 的缓存存活时间很短，所以间隔很久之后的第一次请求会重新按全
  价付费。这里把它算成了便宜的读取，这正是那个数字是下限的原因。
- **补全部分。** 一个不上报输入计数器的运行时同样不上报输出，所以输出 token 被留作
  零，而不是被凭空造出来。

credit 数字会原样一并列出。两者是互相独立的事实——一个是运行时自己的精确记账，另一个
是推导出的 token 乘公开单价——任何一个都不会被换算成另一个。

一部分请求能定价、另一部分不能的会话会被标为 `partial`，它的总额会被标为下限。

## 货币

`currency` 是一个**标签**。AIProbe 永远不做任何换算，因为那需要一个它没有诚实途径获
取的汇率。

设置它的用处是：当你用自己的货币填费率时，报告就不会再声称你的欧元数字是美元。能识别
符号的是 USD、EUR、GBP、JPY、CNY；其他一律渲染成代码后缀（`12.34 SEK`），而不是被装
成美元。

跨会话汇总时，货币不一致的一组会话**不会**被相加。汇总会标出这一点，并把币种不同的会
话计为未定价。

## 关掉它

任何分析命令上的 `--no-cost` 都会移除花费区块、标题区的金额、以及每条发现的花费。JSON
会整个省掉 `spend` 而不是输出一堆零，这样使用方能区分「定价被关掉了」和「这个不花
钱」。

## 读 JSON

```console
$ aiprobe pricing --json          # 生效的价目表
$ aiprobe report --json           # 一份报告，含它的 spend 区块
```

`spend` 对象携带数字及其来源：

| 字段 | 含义 |
| --- | --- |
| `known` | 到底有没有确定出花费。为 false 时看 `unknown_reason`。 |
| `total` | 会话花费，拆成四类加一个总计。 |
| `recoverable` | 浪费值多少钱。`estimated` 恒为 true。 |
| `prompt_tokens`、`prompt_cost` | 账单的上下文一侧，不含补全。 |
| `effective_input_rate` | 上文说的混合单价，每百万 token。 |
| `modelled` | 数量与缓存划分是推导的，不是实测的。这个数字是下限。 |
| `ceiling`、`ceiling_tokens` | 全部未缓存的上限，`modelled` 为真时存在。 |
| `by_model` | 每个被计费的模型一行，带各自的用量、花费和四种费率。 |
| `unpriced_models` | 用到但没有费率记录的模型，只可能在关掉兜底时出现。 |
| `approximated_models`、`approximate` | 按通用单价计价的模型，以及总额里是否有任何部分如此。 |
| `fallback_rate` | 通用输入单价，好让报告能说出它是用什么近似的。 |
| `partial` | 一部分请求定了价、一部分没有：总额是下限。 |
| `discount`、`multiplier` | 同一个折扣的两种表述。 |
| `price_source` | `default`、`config` 或 `mixed`。 |
| `prices_as_of` | 内置表的日期。 |
| `config_error` | 存在价格文件但读不出来时设置。 |

每个 `Cost` 对象都带 `estimated`，而且花费会继承它所依据的 token 的来源属性：估算的
token 产生估算的花费，渲染器标注它的方式与标注估算 token 数完全一致。
